# 客户端与服务端版本检查

从 `2.6.24-tcp.3.2` 开始，客户端通过独立的 `voicechat:version` 通道上报发行版本和协议编号。服务端返回自己的版本。两端发行版本不一致时，玩家聊天栏和客户端日志显示提示，服务端控制台记录玩家名称、UUID、客户端版本及服务端版本。Velocity/BungeeCord 同样记录客户端与代理插件的版本差异，并转发后端的版本诊断。

比较发行版本时忽略 `+` 后的 Minecraft 版本后缀。因此，同一发行版本的不同 Minecraft 客户端通过代理连接时，不会仅因游戏版本后缀不同而被误报。

版本不同只产生提示；实际是否能连接，仍由 UDP/TCP 协议协商决定。没有共同协议时，服务端拒绝初始化语音并发送不兼容提示，不会因这个提示踢出 Minecraft 游戏。

旧客户端没有上报发行版本的能力。服务端会显示“客户端未提供发行版本”、已知的客户端协议编号和自己的发行版本，建议更新客户端。不能据此推断旧客户端的准确 jar 版本。

新客户端先尝试版本检查；若 1.5 秒内没有收到回复，使用旧版四字节密钥请求，以兼容旧服务端的严格解码器。收到服务端版本回复后，才使用带 UDP/TCP 能力声明的扩展请求。5 秒内没有版本回复时，客户端会提示服务端未提供版本信息，而不是将其误判为确定的版本不兼容。

服务端及代理根据请求是否携带扩展来生成响应：旧客户端的密钥包在 `allowRecording` 字段结束；新客户端的扩展密钥包才追加四字节传输协议。这样避免旧客户端收到额外四字节后发生 `custom_payload` 解码错误。

无需新增配置项。建议客户端、后端和代理一起更新，以获得完整的双端诊断信息。发行版本由客户端自报，仅用于兼容性诊断，不作为权限或身份认证依据。

Paper/Folia 服务端必须安装匹配 Minecraft 版本的 Paper 插件包。插件会在 bootstrap 注册命令前检查游戏版本，避免错误版本的插件被禁用后，玩家登录时异步构造命令树仍调用已关闭的插件类加载器。
